# 2026-11-26 过程记录

主题：Cloudflare + B2。运维手册见 [../README.md](../README.md)，Worker 源码见 [../img-up.js](../img-up.js)。

## 时间线

1. **ECS 静态站上线**：构建 `imsyy/home` → rsync 到 `/var/www/home`，原生 Nginx（不装 Docker，省内存），gzip_static + 静态长缓存。装 vnstat 做流量统计。
2. **Cloudflare Tunnel**：装 `cloudflared`，面板授权后建隧道 `huawei-home`，接入 `home` / `demo` / `verify` 三个子域，systemd 常驻。
3. **Access**：先给 `demo` 加邮箱 OTP，后改为只保护 `verify`，策略为 `@qq.com` / `@139.com` 后缀。
4. **Worker 示例**：部署 `api-demo`，绑定 `api.xzqf.nyc.mn`。
5. **Pages 图床**：建项目 `xzqf-img`，绑 `img.xzqf.nyc.mn`，服务器上沉淀为 `~/tools/cf/img/`（脚本 + 配置 + 图片源 + 日志），命令 `upimg`。
6. **B2 手机上传通道**：建私有桶 `xzqf-img`（us-east-005），Worker `img-up` 用 SigV4 直传直读，提供上传页、图库 `/g`、列表 `/list`、删除 `/delete`、直链 `/f/`。
7. **边缘加固**：缓存规则（`up/f/*` 30 天、`img` 遵循源站）、WAF 拦截敏感路径、Bot Fight Mode、Always Use HTTPS。
8. **Email Routing**：确认 2024 年已配置 catch-all，任意前缀邮箱均可转发。
9. **密钥轮换**：上传密钥、B2 Application Key、CF API Token 全部轮换；ECS `authorized_keys` 去重，沙箱公钥固定注释 `trae-sandbox`。
10. **文档归档**：运维手册存沙箱 / ECS / B2（Access 保护）/ GitHub 私有仓库；旧公开版本删除并清理边缘缓存。

## 关键结论（踩坑记录）

- **`workers.dev` 在大陆不可达**：Worker 必须绑自定义域名才能用。
- **Pages 是整站快照**：每次部署以源目录为准，不能只传增量文件。
- **B2 公开桶需要付款记录**：私有桶 + Worker 代理可完全绕开绑卡。
- **删文件 ≠ 下线**：CF 边缘缓存仍在，必须 Purge（自定义 URL）才算真正失效。
- **免费版没有 Rate Limiting 权限**：用 Worker 内存计数做尽力而为的限流。
- **CF Token 权限分 Account / Zone 两组**：建 Access 应用要 Account 权限，DNS/缓存/WAF 要 Zone 权限；改完必须保存到底。
- **沙箱环境会重置**：SSH 私钥、临时文件可能丢失，重要源码要落在 `/workspace` 或仓库里。
